## 2023-10-27 - Pre-allocating Vec in daemon RPC layer
**Learning:** Found an O(N) memory reallocation bottleneck in `pim-daemon`'s RPC layer where `Vec::new()` was used instead of `Vec::with_capacity()` for processing discovered peer tables, despite the final size (`table.len()`) being known upfront. This reallocation overhead occurs on a hot path queried by clients.
**Action:** Always check loop allocations on hot paths. When iterating over a collection to build a corresponding output vector, explicitly specify the capacity using `Vec::with_capacity(expected_len)` to avoid unnecessary heap reallocations.
